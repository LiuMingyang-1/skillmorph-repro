# SkillMorph 复现计划

目标是复现「执行任务 → 抽象轨迹 → 可疑动作定位 → 修改 skill → 重跑验证」的完整流程。先把各部分的职责和数据流划清楚，再逐步实现。

**当前进度**：单轮 pipeline 已实现（`pipeline.py` / `python -m skillmorph`）：已有轨迹 + skill → abstraction → attribution → revision，每次独立运行产物写 `runs/run_NNN/`。execution（任务执行/判分）、evaluation（修订后重跑对比）、多轮历史（Eq.5-7）均未实现，留待后续。

**后续测试环境方案**：以 SWE-Skills-Bench / CTA 为候选来源的资料剥离、环境搭建与分阶段 TODO 见 [BENCHMARK_ENV_PLAN.md](BENCHMARK_ENV_PLAN.md)；目前仅完成方案与静态调查，尚未接入运行环境。

## 目录与职责

算法按方法阶段组织；数据集及其初始化、执行和判分放在独立数据集目录，阶段内部按实际需要拆文件。

```text
skillmorph/
  abstraction/      # 轨迹整理、状态迁移抽象、动作聚类
  attribution/      # 错误引入判断、覆盖统计、历史调整、可疑动作打分
  revision/         # skill 内容定位、修改建议、评估合并与修改应用
  llm.py            # OpenAI API 调用，供需要 LLM 的阶段共用
  pipeline.py       # 串联各阶段，控制演化轮次、传递本轮和上一轮结果
  config.py         # 模型名、重复次数、top-n 等少量参数
datasets/
  swe_skills_bench/ # 数据、初始 skills、环境初始化、执行、判分及轨迹转换
experiments/        # 实验配置、提示词、Skill 快照和结果集中放在这里
  exp_001/          # 一次独立实验，名称可附简短说明
    prompts/        # 本实验初始的抽象、错误判断、定位、修订提示词
    skills/         # 本实验初始的 skill 及其引用文件
    data/           # 任务、数据集划分或已有轨迹
    runs/
      run_001/
        prompts/       # 本次运行实际使用的提示词副本
        skills_before/ # 本次运行前的 skill
        trajectories/  # 本次运行实际使用的输入轨迹
        analysis/      # 抽象、动作映射、覆盖计数和可疑动作排名
        revision/      # 定位证据、修改建议、理由和 diff
        skills_after/  # 本次运行修订后的 skill
        raw/           # chat_json 解析失败时保存的原始模型回复
      run_002/        # 后续独立运行沿用相同结构，自动编号
    summary.md      # 本实验的设置说明、主要结果和结论
tests/              # 覆盖计数、打分等关键逻辑的测试与小样例
docs/               # 本计划和必要的方法说明
```

- **`datasets/<数据集>/`**：集中保存该数据集的任务、初始 Skill、测试、初始化、执行、判分和轨迹转换。优先复用已有机制，向方法层输出约定 JSON，不把数据集特例写入 `skillmorph/`。一次性整理脚本可在整理完成后删除。
- **`abstraction/`**：把原始日志整理成状态迁移序列，用 LLM 提取动作，并通过层次聚类统一同义动作，输出可用于统计的动作 ID 和出现位置。
- **`attribution/`**：根据轨迹结果和动作上下文构建覆盖统计，结合上一轮计数计算可疑程度，输出排名及对应证据。它只负责找可疑动作。
- **`revision/`**：根据可疑动作、执行证据和 skill 内容，定位需要修改的文件和位置，生成建议，再评估、选择、合并并应用。原始 skill 保留，修改结果写入本轮目录。
- **修订前后对比**：复用数据集目录中的执行和判分入口；实验目录保存结果，先输出成功次数、改善和退化，不为单个数据集在方法包内建立专用 evaluation 模块。
- **`pipeline.py`**：负责执行顺序和轮次。具体的抽象、打分、修改逻辑放在各自目录里。

`llm.py` 当前只封装 OpenAI 调用，不设计多供应商后端；API key 从环境变量读取。

## 实验文件集中管理

每次新实验在 `experiments/` 下单独建一个目录。实验使用的 prompts、Skill 快照、任务选择、数据划分和结果放在实验内；可复用的基准资料与运行适配集中在根目录 `datasets/`，实验只引用数据集版本和任务 ID。已有 exp_001 合成轨迹原样保留。根目录不再单独设置 `prompts/`、`skills/`、`data/` 或 `runs/`。

实验根目录的 `prompts/` 和 `skills/` 保留初始版本；每次独立运行保存实际使用的提示词，以及修订前后的 skill。每次运行都从实验根目录读取输入，不自动读取上一次运行的 `skills_after/`，不覆盖已有运行目录。

同一实验的各次运行放在 `runs/`（`run_001`、`run_002`…自动编号）；独立对照或更换实验设置时另建实验目录。大型外部数据集可以在实验的 `data/` 中记录路径和所用任务清单，不必重复复制。

## 各阶段如何衔接

```text
任务 + 当前 skill
  → execution：执行轨迹、成功／失败结果
  → abstraction：状态迁移、统一动作及其出现位置
  → attribution：可疑动作排名、覆盖计数、执行证据
  → revision：修改后的 skill、修改理由和 diff
  → evaluation：修订前后对比
```

各阶段先用普通 Python 数据和 JSON 交换结果，约定好实际需要的字段即可。结果统一保存在 `experiments/<实验名>/runs/run_NNN/` 的对应子目录；多轮演化时的历史机制未实现，届时再按论文约定，不另建记忆系统。

## 方法上需要保留的部分

- 每个任务默认独立运行 3 次，保留全部轨迹。
- 保留论文的状态迁移抽象和层次聚类。同义动作的 ID 要统一，多轮统计时也要保持可比。
- 失败轨迹中的动作计失败覆盖；成功轨迹也要判断动作是否引入错误。每个 run 对同一动作的成功、失败覆盖分别去重。
- 有历史时，按论文先在各任务内调整计数，再跨任务聚合打分；首轮没有历史就直接计算。
- 修订包含定位、生成建议、评估、选择和合并，并利用已有的修订历史。保存证据、修改理由和 diff，便于人工核查。

## 已知实现假设与当前优先级

优先补齐执行、判分和多轮框架，聚类质量暂记为已知限制，后续再做对照与调参。
[SkillMorph §4.1](https://arxiv.org/html/2610.11858v1#S4.SS1) 未披露具体聚类输入、模型、距离或阈值；当前 action-only embedding + cosine + average linkage + 0.5 是本项目的实现选择。
其引用的 [FAMAS 预印本 §4.1](https://arxiv.org/html/2509.13782#S4.SS1) 描述按 agent 分组后由 LLM 对 action–state 做语义分组，但不能据此认定 SkillMorph 完全照搬。
提案筛选由 LLM 完成；完整方法还包含后续轮次的任务执行及留出任务评测，不能把提案通过视为效果验证。

## 实现顺序

1. **先做轨迹到修改的流程。** 用少量真实轨迹和 skill，完成抽象、归因和修订。人工检查中间结果，用手算样例核对计数和打分。
2. **接入选定数据集。** 数据集由用户另行选择；接入任务执行和判分，串起完整一轮，比较修订前后的结果。
3. **再跑多轮。** 保留上一轮计数和修订历史，检查历史调整是否正确，以及效果是否稳定。正式效果评估使用独立验证任务。

当前架构只服务这条流程。vLLM、本地模型部署、hidden states、多后端适配、缓存计费、并发调度、断点续跑和完整报表都留待实际需要时再考虑。
