# SWE-Skills-Bench 测试环境接入方案

日期：2026-10-27。本文是待执行方案；当前只编写文档。Docker 由用户准备好后再开展环境搭建，不启动容器、不安装软件、不调用付费模型。

## 目标与实施顺序

先建立能重复执行、可靠判分、切换 Skill 版本的测试环境，再接入已有 SkillMorph 流水线，最后研究内部状态与外部轨迹的联合使用。

最小闭环：固定任务起点 + Skill v0 → 执行与判分 → 轨迹 → SkillMorph 修订得到 v1 → 重置任务环境 → 使用 v1 重跑与判分。

首先用一道题验证接线；随后扩到同一 Skill 的多个不同任务，划分演化集和留出集。单题跑通只证明基础设施可用。

- [HF 官方数据](https://huggingface.co/datasets/GeniusHTX/SWE-Skills-Bench)：JSONL 是主要数据，README 解释字段与许可，`.gitattributes` 是 Git 文件管理配置。
- [CTA 第三方仓库](https://github.com/explicitcontextualunderstanding/cta)：包含相关基准资料和执行框架；CTA 指 Counterfactual Trace Auditing，是另一项研究的方法。
- 本次检查的 CTA 提交：`8822baed308a74b5921e2a5be50394c1a4a8fc96`。后续下载与提取固定到此提交，变更版本另记原因。
- CTA 根目录 LICENSE 为 MIT，复制实质代码或资料时保留版权和许可；Skill 包自身的许可与目标项目许可另行核对。
- 该仓库不能直接视作 SWE-Skills-Bench 官方发布版，也不能保证等同于 SkillMorph 的原实验输入。来源、差异和自行修补内容均须记录。
- 已知事实与未验证事项见 [可用性调查](SWE_SKILLS_BENCH_CHECK.md)。

| 来源路径 | 用途 | 处理方式 |
| --- | --- | --- |
| `config/benchmark_config.yaml` | 仓库地址/commit、镜像、初始化、命令和限制 | 按所选 Skill 提取必要配置；核对嵌套层级、重复键和默认值 |

| `tests/batch*/_dependency_utils.py` 等实际依赖 | 测试辅助模块 | 按 import 依赖补齐，不能只复制单个测试文件 |
| `skills/<skill>/` | 初始 Skill 及引用文件 | 提取完整包，保留 LICENSE；核对与 HF 版本差异 |
| `src/orchestrator/docker_manager.py` | 容器创建、文件传输、命令执行、清理 | 参考或按需适配；不整体搬入框架 |
| `src/orchestrator/lifecycle.py` | 克隆、检出、初始化、Skill 注入等顺序 | 作为流程参考；改成显式输入路径和版本，避免依赖当前目录 |
| `src/initializer/`、配置引用的 `patches/` 等 | 创建指定任务起点 | 逐题追踪真实依赖；保留必要的 fresh/degradation 语义，不能略过预处理 |
| `src/proxy/claude_code_proxy.py` | Claude Code 执行与原始日志收集 | 可参考现成执行方式；适配轨迹，不能假定能取得 hidden states |
| `src/evaluator/` | 构建、测试调用及结果解析 | 复用思路和必要实现，单独核对成功条件 |
| `main.py`、`eval.py`、`run_all_skills*.py` | 理解调用关系与配置传递 | 先作参考，首版只做单任务串行入口 |

以下内容首阶段不引入：`src/cta/` 的反事实分析、CTA 输出和历史结果、论文图表生成脚本、全量批处理调度、与所选任务无关的资料和依赖。

`containers/` 中的 Dockerfile 可能是 CTA 特定实验镜像，不能默认等于基准镜像构建配方。只有追踪到所选任务依赖时才采用。

## 如何剥离与落盘

1. 把固定提交的 CTA 检出到独立本地目录，作为只读来源，不把整仓库塞进本项目。
2. 一次性整理所需任务、测试、辅助文件和完整 Skill 包到 `datasets/swe_skills_bench/`，保存来源清单。临时提取脚本放在临时目录，整理完成后可删除，不规划永久的 `scripts/prepare_swe_skills.py`。
3. 初期按选定任务手工核对依赖闭包，不先开发通用打包系统。测试、初始化脚本、引用文件缺失时明确报错。
4. 数据集专用的初始化、执行、判分和轨迹转换放在该数据集目录内。`skillmorph/` 保留抽象、归因、修订及轮次编排，不加入 SWE-Skills-Bench 专用分支，也不预建通用执行框架。
5. 整理后运行不依赖完整 CTA 检出或临时脚本。仓库只保留实际运行所需资料、许可、来源与必要差异记录；无需保留 CTA 分析代码、下载缓存或重复备份。

拟议结构（尚未创建）：

```text
datasets/
  swe_skills_bench/
    README.md                      # 来源、固定版本、运行方式、适配差异
    LICENSE                        # 保留来源许可；Skill 自带许可随包保留
    manifest.json                  # 任务/批次映射、repo commit、镜像与文件哈希
    tasks/                         # 任务描述
    skills/                        # 数据集提供的初始 Skill 包
    tests/                         # 验收测试与所需辅助文件
    setup.py                       # 此数据集的环境初始化/重置（普通脚本）
    run.py                         # 显式接收任务、Skill 路径和输出目录
    evaluate.py                    # 此数据集的验收判分
skillmorph/
  abstraction/
  attribution/
  revision/
  pipeline.py                      # 方法流程及后续轮次编排
experiments/exp_002_swe_pilot/
  prompts/                         # 现有分析与修订提示词
  skills/                          # 本实验初始 Skill 快照，可为数据集中的子集
  data/
    dataset.json                   # 引用数据集版本、任务 ID、运行配置
    split.json                     # 演化/留出划分
  runs/run_NNN/
    ...                            # 沿用现有 prompts/analysis/revision 等目录
    execution/                     # 配置、原始日志、退出码、项目改动
    evaluation/                    # 任务验收结果；区别于 revision/evaluation.json
```

文件名是职责建议，实施时可按实际代码量合并；不要为了目录完整而建空模块。`setup.py` 是数据集初始化脚本，不是 Python 包安装入口。

数据集目录保留可重复使用的资料与适配代码；实验目录只保存所选配置、Skill 快照及运行结果，不重复复制整份数据集。新增数据集时增加同级目录，不改写 SkillMorph 的算法模块。数据集专用适配测试也留在该目录，根 `tests/` 继续测试方法代码。

大型镜像和项目代码存于 Docker/外部工作目录，实验只记录不可变标识，不提交镜像、凭据或目标项目完整副本。

## 任务和环境固定原则

- 每次任务执行从相同的项目 commit、初始化步骤及依赖快照开始。前一次智能体改过的代码不带到下一次。
- 镜像记录 digest 与平台，不能只记 `latest`。检查 Apple Silicon 与 amd64 镜像兼容性；必要时采用 Linux 执行机，并将平台差异写入记录。
- 外置硬盘上的 Docker 由用户准备；届时检查 CLI、context、daemon、磁盘空间和共享路径，不擅自移动镜像存储或重装。
- 每次只注入指定 Skill 树，记录内容哈希；清除上一版本和无关 Skill，核查 CLI 实际加载位置及项目内额外指令。
- 固定执行模型、工具、提示词、超时、重复次数及预算；保留每次随机运行的结果，不挑选成功轨迹。
- 测试和答案不进入执行智能体可读工作区；正式验收在执行结束后的独立阶段完成。原生项目测试是否可读按任务协议固定。
- 初始化/预处理如需模型生成或会改变代码，必须先生成固定任务起点，再供所有对照共享；不可每个方法重新随机构造任务。

## 判分与日志接口

CTA 的 `unit_test_runner.py` 支持 `min_pass_rate`，不能直接把其状态当成本项目的任务成功。所选基准协议要明确：哪些测试必须通过、跳过如何处理、是否存在构建或其他检查。

- 保存 passed/failed/skipped/errors、测试数量、退出码、耗时与日志。测试收集失败、零测试或执行环境失败不能报告成功。
- 区分正常执行后的任务成功/失败，与环境初始化失败、智能体运行异常、判分器异常。任务超时按预先固定协议计失败；基础设施异常保留为无效运行并单独报告。
- 默认按所有必需检查通过认定成功；如与来源阈值不同，标为适配差异，不声称完全复现原判分。
- 任务描述与测试冲突、只匹配关键词、扫描到原有代码即可通过等情况要审查。修改测试则保留原版和 diff，单列改编结果。

数据集目录中的执行适配输出现有接口所需的 `task_id/run_id/task/outcome/steps`。步骤保留工具调用、观察、Skill 和文件查阅线索，原始日志另存，不编造缺失使用记录。方法层只消费这个普通 JSON 接口；后续重跑通过显式传入的执行/判分入口连接，不硬编码数据集名称。

额外记录 task/skill/batch、Skill 哈希、repo commit、镜像 digest、模型及配置、运行状态、测试统计、usage/费用（未知值不能写成零）。只有得到有效任务判分的轨迹进入现有成功/失败覆盖统计。

## 分阶段 TODO 与验收标准

### P0：资料提取与单题选择（不依赖 Docker）

- [ ] 下载固定 CTA 提交，保存许可及来源清单；固定 HF 数据 revision/hash。
- [ ] 对齐 task、Skill、test、辅助文件、初始化与 repo commit；检查实际 batch 配对，不能把文件数直接当有效任务数。
- [ ] 选一个轻量、依赖少、功能测试明确的任务作为试点；`fix`、`tdd-workflow` 可作候选，但须先核对初始化与测试质量，不提前认定合适。
- [ ] 检查同一 Skill 的其他批次是否提供足够不同任务，能否构造演化/留出集。
- [ ] 整理得到独立可用的 `datasets/swe_skills_bench/`；核对缺项，清理临时提取脚本、下载缓存和无关 CTA 文件，保留必要来源与许可。

验收：可从固定来源生成一个完整、可追踪的任务包；其运行命令、起点与成功条件明确。

### P1：Docker 和判分器验证（用户准备 Docker 后）

- [ ] 验证 Docker context/daemon、外置盘访问、平台、磁盘与网络；确认镜像可获取并记录 digest。
- [ ] 启动独立容器，检出项目、安装依赖、执行必要预处理，保存任务起点。
- [ ] 无模型调用地完成测试收集与未修改起点判分；检查失败来自未完成任务还是环境问题。
- [ ] 用已知正确实现和已知错误实现验证判分区分能力，排除空测试、全部跳过或明显误通过。
- [ ] 连续初始化两次，确认项目起点和测试输入一致，容器及临时文件可清理。

验收：环境可重建；判分可靠区分实现；没有依赖付费模型才能诊断的环境故障。

### P2：执行任务与保存真实轨迹

- [ ] 确定执行模型/智能体与首次付费试跑预算；届时确认具体配置，再开始模型调用。
- [ ] 单题 + 初始 Skill 执行一次，收集原始日志、项目 diff、资源用量与验收结果。
- [ ] 转换为现有 trajectories 格式，核对步骤顺序、观察和 Skill 查阅记录。
- [ ] 在 `datasets/swe_skills_bench/` 完成执行/判分适配，输出方法层所需 JSON；环境异常不混入覆盖计数。

验收：得到一条来源完整、能供现有流水线读取的真实轨迹与可复查判分。

### P3：接通 Skill 修改前后对比

- [ ] 由真实演化轨迹运行现有 abstraction → attribution → revision，保留 Skill v0/v1 和 diff。
- [ ] 在重置环境中执行 v1，与 v0 使用相同任务协议；检查实际加载的 Skill 哈希。
- [ ] 扩到一个 Skill 的多个任务；预先冻结演化/留出划分，默认每任务独立运行 3 次。
- [ ] 汇总 trial-level accuracy、pass@3、三次全成功比例、改善/退化、时间与成本。
- [ ] 留出结果不反馈给修订，不据其选择提示词、层或版本；开发调参需要时另设开发集。

验收：真实“执行—修订—重跑”闭环成立，能输出留出任务的前后对比；单轮结果不称为完整多轮复现。

### P4：多轮与内部状态（后续）

- [ ] 实现显式轮次控制、跨轮动作对应、Eq.5–7 计数调整和修订历史；不要把独立 run_NNN 当演化轮次。
- [ ] 内部状态实验前确定采集对象：执行模型，或读取轨迹的诊断模型。仅调用远端 CLI/API 不等于能获得 hidden states。
- [ ] 增加可访问激活的模型执行/诊断方式，并保存动作与 token/层信号的对应关系；不要求首版先做通用多后端系统。
- [ ] 同起点、同执行模型、同修订器、同数据划分与预算下，比较外部证据、内部证据、内外结合；记录探针训练数据和额外成本。

验收：能把增益归于迭代方法，而非更换执行模型、扩大预算或接触留出信息。
