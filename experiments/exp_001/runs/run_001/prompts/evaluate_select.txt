You are evaluating revision proposals for an agent skill set and consolidating
the selected ones into a patch.

## Input (JSON)

- `proposals`: each with `action_id`, `rationale`, `edits`, plus `evidence`
  (suspiciousness score, failure/success-covering runs, tasks) and
  `occurrences` (execution contexts of the action, including the per-occurrence
  `introduces_error`/`error_reason` judgments where they exist — null means
  the run was not judged, not that the step was clean).
- `skill_contents`: the complete current contents of every file in the skill
  set, as {path, content}.

$proposals_json

## Your task — reason through three steps before answering

1. Evaluate each proposal on three aspects:
   a. Evidence: the action's suspiciousness score and the runs/tasks providing
      failure coverage, together with the localization rationale — how strongly
      is the problem established and how certain is the localization?
   b. Fit: compare the proposal with the current skill contents around its edit
      sites — does it duplicate or conflict with existing guidance, or change
      more than the evidence supports?
   c. Risk: the successful runs that rely on the edited contents — could the
      change disrupt guidance that supports successful executions?
2. Select the high-value proposals; reject the rest with a reason.
3. Consolidate the selected proposals into one patch, resolving overlaps
   between them.

Return only a JSON object — no prose, no markdown code fences:
{"selected": ["<action_id>", ...],
 "rejected": [{"action_id": "...", "reason": "..."}, ...],
 "files": [{"skill": "...", "artifact": "...",
            "content": "<COMPLETE new content of the file>"}]}

The response must be strictly valid JSON: inside strings escape backslashes
as \\ and quotes as \" (never write a single backslash such as \s or \p;
for example Windows paths appear as "C:\\tmp\\file"); use \n for newlines
inside strings; no comments or trailing commas.

Rules for `files`:
- `files` may only contain the consolidated result of the SELECTED proposals.
  If `selected` is empty, `files` must be empty — nothing is applied otherwise.
- `content` must be the entire resulting file, not a fragment or a diff.
- Include only files that actually change; unchanged files are copied as-is.
- Keep each changed file consistent: all selected edits to it merged, overlaps
  resolved.
